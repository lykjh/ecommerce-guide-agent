## 1. Agent现有传输与信任范围（C01）

基础地址来自`MALL_BASE_URL`，通过`config/app.yml`的`mall.base_url_env`指定变量名；开发示例`http://localhost:8080`，可包含部署前缀。只接受http/https及有效netloc。三个商品接口使用GET、无body，不携带登录Cookie、模型Key或用户身份，不自动重试。

成功包络为`{code:integer,message:string,data:T}`，其中code必须200。适配器先读取真实HTTP状态，再校验包络与本项目消费的data模型。失败不能默认成空结果。金额来自商城BigDecimal/JSON number，Python按`json.loads(parse_float=Decimal)`解析，以Decimal比较，不经float计算价格。

## 2. Agent当前消费的查询接口（C02）

| 路径 | 专用参数 | 成功data |
| --- | --- | --- |
| GET `/discovery/products` | `q?:string`最长100字符；`cursor?:string`不透明游标 | `DiscoveryPage` |
| GET `/products` | `afterId?:positive integer` | `ProductPage` |
| GET `/products/{id}` | 路径`id:positive integer` | `ProductDetail` |

搜索与列表共用可选query：`categoryId`、`brandId`、`shopId`均为严格正整数；`minPrice`、`maxPrice`为非负有限十进制金额，min不得大于max；`size`为严格整数1..100。商城研究基线的默认size为20，**Agent请求模型当前默认size为3**。参数为None时不发送。

关键词只走`/discovery/products?q=...`，不把q传给`/products`。搜索不发送page/afterId；列表不发送page/includeTotal。三接口均没有color参数，也没有全量total。当前节点按用户品类文本做关键词搜索，中文品类到categoryId映射尚未接入；不能把适配器支持categoryId视为自动分类已完成。

游标原样保存：搜索nextCursor为字符串，下一次传cursor；列表nextCursor为整数，下一次传afterId。更改条件必须新开查询。身份接入后的游标身份绑定另由商城契约确认。

## 3. Agent当前消费的响应字段（C03—C04）

以下是**Agent实际消费并校验的最小schema**；上游可返回更多字段，当前模型忽略未消费字段。`?`表示值允许null，不表示允许缺字段；下面列出的data响应字段均必须出现。

| 模型 | 字段与类型 |
| --- | --- |
| ProductCard | `id:positive integer`，`name:string`，`startingPrice:nonnegative decimal|null`，`soldOut:boolean` |
| DiscoveryPage | `items:ProductCard[]`，`hasMore:boolean`，`nextCursor:string|null` |
| ProductPage | `items:ProductCard[]`，`size:integer[1,100]`，`hasMore:boolean`，`nextCursor:positive integer|null` |
| ProductDetail | `id:positive integer`，`name:string`，`description:string|null`，`options:ProductOption[]`，`skus:ProductSku[]` |
| ProductOption | `id:positive integer`，`name:string`，`values:OptionValue[]` |
| OptionValue | `id:positive integer`，`value:string` |
| ProductSku | `id:positive integer`，`optionValueIds:positive integer[]`，`price:nonnegative decimal`，`available:boolean` |

ID及boolean是严格类型，不能用字符串或整数冒充boolean。字段集合不可为null；description允许null，SKU价格必须明确；起售价可null，不能当作匹配SKU价格。SKU没有公开库存数量，available仅表示查询时可售。

当前商城VO还包含封面、品牌、店铺、销量、图片、分类路径等字段；本项目暂不消费，完整非空保证与图片访问协议不在此接入schema内，不能据此自行输出商品链接/库存数量等未核实数据。

成功空结果仅指code=200且`items=[]`。当前展示本批核实数量和hasMore，不把items长度或核实数量当成全商城总数；hasMore指搜索候选页，不保证后续候选均满足SKU颜色等条件。

## 4. SKU证据规则

推荐/概览一轮读取一页，最多查前三个候选详情，实际HTTP均经共享查询预算；未检查的候选记为未核实。匹配必须在**同一SKU**同时满足可售、价格上下限和颜色，不能用黑色SKU的颜色配另一个SKU的价格。

颜色只取名称恰为“颜色”的唯一结构化option，并按SKU的optionValueIds关联唯一颜色值；缺失、多个颜色option或关联不明确时不猜。无颜色限制则无需颜色证据。匹配结果证据只保留匹配SKU，不从标题推断颜色，不无限翻页、扫全库或引入缓存/重试。详细函数行为见[内部工具契约](内部工具契约.md)。

## 5. 错误约定（C05）

商城研究基线包含400参数、401会话、403拒绝、404不存在、409冲突、429限流、503依赖不可用、500非预期错误；并非每个商品端点均已实测全部状态。Agent保留实际HTTP状态和可验证的整数业务code，不虚构新的商城数值码。

| 适配层分类 | 条件及处理 |
| --- | --- |
| `configuration` | 商城基础地址缺失或格式无效 |
| `network` | 可识别的网络/连接/HTTP底层错误；没有可靠业务code |
| `response` | 成功HTTP中的JSON、包络或data不合schema |
| `http` | HTTP≥400；即使正文非JSON也保留状态；正文合法才提取业务code |
| `business` | HTTP未报错但包络code不为200 |
| `TimeoutError` | 超时原样传给预算层，转为查询超时终止，不伪装成无结果 |

`MallError(kind,http_status=None,code=None)`只携带可记录元数据，不存自由错误正文。商品不存在的404在对象解析业务层可转not_found；查询适配层不吞404为空列表。搜索索引未就绪历史示例是HTTP503/code503，不是零商品。商城日志只记端点模板、状态、分类、耗时、request_id，不记query、凭据或响应正文。

## 7. A-1.0分类接口契约（shiwushop源码确认）

本节已按当前shiwushop源码重新核对，来源相对该后端根目录如下：

- `shiwushop-app/src/main/java/com/shiwushop/product/controller/category/CategoryController.java`：路径及参数。
- `shiwushop-core/src/main/java/com/shiwushop/product/service/impl/CategoryServiceImpl.java`及同模块`product/vo/category/`：可见性、层级、排序、响应字段。
- `shiwushop-core/src/main/resources/mapper/ProductMapper.xml`与`shiwushop-search/src/main/java/com/shiwushop/product/search/DiscoveryService.java`：分类后代范围。
- `shiwushop-app/src/main/java/com/shiwushop/common/GlobalExceptionHandler.java`：业务异常到HTTP状态及包络code映射。

以上为静态证据，不包含运行服务或真实数据验收。

基础地址仍读MALL_BASE_URL；公开只读GET，不添加登录凭据。成功使用既有`{code:integer,message:string,data:T}`包络，不新增外层协议。

| 方法/路径 | 输入 | 成功data | 已核对失败语义 |
| --- | --- | --- | --- |
| GET `/categories` | 可选query `parentId:positive integer`；省略表示一级分类，不以0代替省略；无body | `CategoryNav[]`，仅请求父节点的直接可见子分类，按sortOrder/id排序；无分页字段 | 显式parentId≤0为业务400；指定父分类不存在或路径含隐藏分类为业务404 |
| GET `/categories/{id}` | 路径分类ID；调用方仅用可信正整数候选；无body | `CategoryDetail` | 分类不存在或自身/祖先隐藏为业务404 |

CategoryNav字段：`id:integer`、`name:string`、`level:integer`、`hasChildren:boolean`、`sortOrder:integer`。CategoryDetail字段：`id:integer`、`name:string`、`level:integer`、`path:CategoryPathItem[]`；路径从根到当前分类，每项`id:integer,name:string`。这些是源码返回字段，尚无真实回包证明全部历史数据的非空约束；不得自行用默认ID/名称补缺失。Nav没有parentId或完整path，父级关系来自本次查询上下文；同名候选展示已有真实祖先路径，不能由模型补路径。

商城分类创建/移动逻辑限制最多三级；真实库是否满足、单层数量和隐藏节点行为须在目标环境核实。列表成功空数组与404/技术失败分开处理。GlobalExceptionHandler将这些业务码同时映射到HTTP状态和包络code，因此源码约定为HTTP400/code400或HTTP404/code404；实际环境响应仍须验证，不将静态核对写成实测通过。

`/products?categoryId=...`包含指定分类及可见后代；`/discovery/products`的分类过滤使用categoryPathIds，适合仍需关键词的查询。仅分类筛选用列表路径；关键词搜索继续走discovery；两种游标保持原类型。此处不授权在无结果或失败时自动切换路径重试。

接口没有按分类名称搜索、全树批量返回或名称全局唯一保证。单个分支命中不能证明没有别处同名；hasChildren也不等于当前回答必须继续下钻。用户选择上级即可按该范围查询。禁止靠遍历所有分支“证明唯一”。
