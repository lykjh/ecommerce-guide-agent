内部工具是确定性Python函数，由LangGraph节点按固定流程调用；当前没有向模型开放任意函数、SQL、URL或无限自主工具循环。外部HTTP分别见[Agent服务接口](Agent服务接口.md)与[商城接口](商城接口.md)。

## 1. 入口与结构化输入

| 接口 | 输入、前置条件 | 输出、失败行为 |
| --- | --- | --- |
| `main_agent.get_ai_stream(user_input: str, thread_id: str = "default")` | 脚本入口校验非空文本、最长6000字符及非空会话ID；多用户调用必须显式隔离会话 | 异步文本生成器；非法输入ValueError；default仅本地示例，不代表身份 |
| `main_agent.stream_reply(user_input: str, thread_id: str, request_id: str \| None = None)` | 参数已由入口校验，消费可信内部会话ID，不二次判空 | 共享会话接纳、预算和流关闭；忙请求只输出忙提示，不进图；异常向上层传播 |
| `IntentRouter.decision(state: AgentState)` | 合法状态、当前用户文本及有界历史 | `tuple[str,list[str]]`；schema/模型失败进入识别失败；预算/取消传播 |
| `MemoryManager.build_messages(state, system_prompt, purpose="answer")` | 消费本会话状态；历史仅数据 | `list[BaseMessage]`；用途决定上下文窗口；不做权限判断 |
| `MemoryManager.summarize_node(state)` | 有可压缩旧消息且预算允许 | 状态增量：summary与RemoveMessage；摘要失败返回空更新，保留原文 |

`RouteDecision`为严格对象，禁止额外字段：`intent`枚举为“闲聊、业务咨询、概览筛选、商品对比、订单查询、商品推荐、政策问答、转人工、澄清、越权拒答、超出范围”；`subjects`为最多8个非空单行字符串，每个1..120字符；`needs_clarification:boolean`。咨询须有唯一可追溯对象，对比至少两个不同对象；代词/颜色本身不构成商品身份。对象来源核对不能替代商城解析与权限。 路由先核对原subjects来自上下文，再将以“商品编号”开头、仅包含一段数字编号和后附非数字属性的对象规范化为编号；普通商品名及含多个数字段的对象不按此规则截取。规范化后仍检查咨询唯一性与对比对象数量。完整用户问题不变，颜色属性继续交给咨询节点结合SKU回答。

`FilterParams`：`category:string|null`最长80、`min_price/max_price:Decimal|null`非负且有限、`color:string|null`最长40、`next_page:boolean=false`、`unsupported_specs:list[str]=[]`，最低价不得大于最高价。unsupported_specs记录仍有效的尺码/容量/版本等非支持硬性筛选要求；非空时节点明确告知尚不支持，不查询后声称满足。仅咨询规格不属于筛选要求。模型每次输出完整新条件，直接替换旧状态；null保留“取消条件”语义，不能再与旧非空值合并。next_page只表示本轮动作，不持久化为用户偏好。

## 3. 商品编排

### `async find_products(request: DiscoveryRequest | ProductListRequest, filters: FilterParams) -> ProductSelection`

根据请求类型选择搜索或列表，一页最多核实前三个详情。输出：

- `matches:list[ProductMatch]`；每个match含`product:ProductDetail`及`skus:list[ProductSku]`，均仅保留符合条件的SKU。
- `page:DiscoveryPage|ProductPage`；保留原游标与hasMore。
- `checked_product_ids:list[int]`；本轮实际核实的详情。
- `unverified_product_ids:list[int]`；未检查或规格证据不明确的候选，可与已检查集合有交集。
- `alternative_colors:list[str]`；本批满足同SKU价格和可售条件、且颜色关联唯一的其他实际颜色值；不代表与用户原颜色等价。

同SKU核实价格、可售和颜色；无匹配正常返回空matches。MallError、BudgetStop和取消传播，不混为无结果。每次HTTP单独占查询预算，最多一页加三次详情，不自动展开所有候选。

### `async resolve_product(subject: str, candidates: list[CandidateRef]) -> ProductResolution`

`CandidateRef={product_id:positive integer,name:string}`，必须来自之前真实商城候选。明确正十进制编号或“商品编号:123”可直接查详情；已有候选精确名称/ID唯一则按ID查询。同名多个候选要求选择。

普通文本发起关键词搜索；仅精确名称唯一且hasMore=false才自动确认，其余返回本页候选让用户选择。无items为not_found。详情404在本业务边界转not_found，其他失败继续传播。

`ProductResolution`字段：`status:"resolved"|"choose"|"not_found"`，`product:ProductDetail|null`默认null，`candidates:list[CandidateRef]`默认空。resolved带真实product；choose带候选；not_found不编造对象。各状态意义由生产者维护，不以相似文本当作商品ID。

## 4. 统一模型与查询预算

`async invoke_model(model, messages, *, purpose="analysis", max_output=1200, schema=None, config=None, timeout=None)`：正式入口在`budget_scope(TurnBudget)`内调用；调用前按输入估计与输出上限原子预留，结束按usage结算，未知用量按预留计入并标记。schema仅用于输入预算估算；实际结构化解析由相应模型/解析边界负责。返回现有client的结果类型。无预算上下文的独立诊断仅受单调用超时约束，不能冒充正式入口完整控制。

`async invoke_query(function,*args,**kwargs)`：同步函数进线程，异步函数在原循环执行；实际HTTP一请求一计数。全进程10个查询名额，满额不排队，抛`BudgetStop("query_busy")`。同步线程在取消等待后继续占名额，直到实际退出；异步取消则回收。没有无限重试。

预算终止统一`BudgetStop(reason)`，当前原因包括`tokens`、`single_call_tokens`、`model_calls`、`repair_calls`、`query_calls`、`model_timeout`、`query_timeout`、`query_busy`、`deadline`、`cancelled`。整轮输出固定停止说明，取消向上层传播。具体上限只在[工程设计的预算章节](../04-工程/工程设计说明书.md#5-预算与终止)维护；源码为`budget.py`。

## 5. 节点状态与输出契约

节点消费已确认的状态，返回增量，不自行猜测上一轮回复：

| 字段 | 类型/用途 |
| --- | --- |
| messages | `list[BaseMessage]`，由add_messages reducer持久化 |
| final_reply | `str`，当前节点定稿；路由每轮先清空 |
| intent / route_subjects | `str` / `list[str]`，当前意图与解析对象 |
| summary | `str`，本会话历史摘要 |
| signal_state | `dict`，闲聊购买信号与强度 |
| task_context | `dict`，当前意图及筛选/商品对象 |
| candidate_products | `list[dict]`，真实商品候选ID与名称 |
| product_page | `dict`，filters、mode（list/search）、category_id、hasMore、nextCursor；模式/分类/条件相同且明确下一批才复用 |
| category_context | `dict`，query、pending、candidates或selected、已确定的mode；路径和ID仅来自真实返回 |
| category_action | `dict`，本轮select/browse/keyword动作及候选零基index；节点结束清空 |

同模式、同分类、同条件且明确下一批时，末页拒绝或商城查询失败保留原product_page；失败不自动重试，用户再次明确请求时仍使用原游标。条件/分类/模式变化仍清除旧分页。分类序号按当前候选数量判定范围，超长数字返回已有越界提示，不进行无界整数转换、不修改6000字符入口限制。

当前TypedDict内的dict字段不是新的外部自由入参schema，浏览器不能直接提交。节点取得可信候选后更新状态；条件完全一致且用户明确下一批时复用游标。已接入的商品节点不使用商品文本向量库代替实时接口。新增政策/订单/人工工具前须先冻结身份、路径、字段、错误及失败语义；不能照本表臆造接口。

## 6. 变更约束

入口校验一次、LLM输出在解析边界校验一次；下游消费合法类型。异步取消不吞掉，具体IO失败只在有明确处理的边界捕获。没有复用/独立语义/独立测试价值的一次性逻辑不另造helper。新增缓存、兼容、重试或额外防御先说明，不为迁就旧测试改变正确业务。共享接口变化须同步生产者、消费者和测试；任务文件所有权由[施工进度](../05-施工进度/施工进度.md)管理。

## 7. A-1.0分类选择与状态交接（目标契约）

本节约束生产者/消费者传递的信息和行为，不伪称存在新的Python函数。实际函数签名和内部存放位置由开发在既有模块内设计，不新增对外API；实现交付须给出本表到实际类型的映射供测试核对。现有HTTP聊天入参仍仅message，不能让浏览器提交可信分类ID或状态。

| 交接内容 | 类型/来源 | 消费约束 |
| --- | --- | --- |
| 分类候选 | 有序集合；每项真实ID(integer)、名称(string)、已核实路径（有序ID/名称项），附查询父级作用域 | 来自商城响应；模型只能从候选中提出选择，不能生成新ID或路径。顺序与展示一致 |
| 已选分类 | 真实分类ID及路径，或空；记录来自用户选择还是上下文可唯一确定 | 修改预算/颜色保留；换品类清除；模型单独选出一个不等于消除歧义 |
| 待选择对象类型 | 分类或现有商品选择语义；没有待选择时为空 | 等待分类时序号先解释为分类，不与candidate_products混用；换话题退出等待 |
| 查询模式与分页 | 当前列表/搜索模式、已确认条件、分类ID、原类型游标和hasMore | 仅同模式、同条件且明确下一批复用；条件或分类变化清旧游标。模式信息不能只凭游标类型猜测 |
| 规格确认 | 用户要求的颜色文本及其确认过的商城实际值；取消为空 | “黑色”与“曜石黑”不自动归一；不同SKU的颜色与价格不得拼接。其他规格要求未获支持时必须告知 |

解析结果要明确区分：已确定分类、需要选择、无法定位且可明确关键词搜索、查询失败。查询失败沿用现有MallError/预算/取消通道，不新造商城业务码；不能转换成空候选表示“没有分类”。待选择的信息保持本会话隔离并可按现有持久状态恢复，不将摘要文字当作可信ID来源。

分类HTTP接入属于mall边界，外部响应在该边界验证一次；分类决策消费合法数据；节点负责用户选择与状态更新；memory只提供现有上下文和持久化，不承担分类匹配。所有实际请求逐次经共享查询预算，内部不能隐藏循环请求。明确需要用户选择时本轮结束，不重复调用直到模型选出一个。
