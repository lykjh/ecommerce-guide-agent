## 1. 首版范围和源码依据

首版仅查询当前买家的订单列表、下一页、选单、详情和包裹。优先使用已存在的三条买家 GET，复数物流路径覆盖多包裹。商城与 Agent 分别在自己的信任边界做检查。

| Agent 服务端调用 | 商城源码行为 | 首版消费 |
| --- | --- | --- |
| `GET /orders?size=5&afterId=...` | 控制器取得登录买家 ID。服务检查账号，校验游标属于同一买家，SQL 固定 `o.user_id`；按创建时间和 ID 倒序。商城默认 20，允许 1～100，拒绝 `page`、`includeTotal`。 | 首次省略 `afterId`，建议一次显示 5 项。只接收 `items / hasMore / nextCursor`，下一页用服务端上一页返回的游标。 |
| `GET /orders/{id}` | 服务层按订单 ID 和买家 ID 联合查询，通过后才解密地址快照。不存在与非本人统一 404。 | 解析严格正整数 ID 后只查指定订单，校验响应 `data.id` 等于请求 ID。 |
| `GET /orders/{orderId}/shipments` | 包裹服务校验账号有效，确认订单属于当前买家，再读包裹。本人无包裹为 200 空数组，单包裹和多包裹均返回数组，非本人或不存在统一 404。 | 直接查复数路径；逐条验证 `orderId` 等于请求订单 ID、包裹 ID 有效且不重复，保持上游顺序。 |

旧 `GET /orders/{orderId}/shipment` 在无包裹时返回 `NOT_SHIPPED`，多包裹时返回 409。首版统一走复数路径。若目标制品缺复数路径，物流项保持待验并固定匹配制品再测。支付、取消订单、确认收货、退款、改地址、商家接口及外部轨迹查询留在对应业务。

## 2. MALLAUTH 与订单归属

1. 浏览器经同源 `/assistant/api/chat` 带上 HttpOnly `MALLAUTH` 和当前小暖聊天 token。商城 Cookie 需覆盖 `/assistant` 和普通商城接口路径。HTTPS 沿用 Secure。Agent 验来源、聊天 token，并通过配置商城的 `GET /users/me` 得到身份，与该聊天绑定的用户 ID 和本次登录指纹比较。身份错配按现有 409 流程拒绝于 SSE 前；游客订单请求引导登录，私有订单 GET 为零。
2. 入口复用已核验身份，在 SSE 生产任务内绑定本请求访问对象，含已验证商城基址、当前 `MALLAUTH`、会话 ID 与登录归属。HTTP 入口通过当轮 SSE 回调显式传入访问对象，凭证仅在该请求的作用域内使用。脚本入口不挂载私有处理器。
3. 用独立的订单适配器只向部署配置的固定商城根地址发上述三条 GET。仅转发当前请求的 `MALLAUTH`，不转发整个 Cookie 头或小暖 token。禁用重定向，接口模板固定，路径和游标只接受有界正整数；用户文字、模型、浏览器参数和历史不能指定上游 URL、身份或任意查询字段。金额以 Decimal 解析。
4. **最终授权由商城逐次作出。** 每条私有 GET 都重新走商城 JWT、账户状态和 Redis 撤销验证，控制器只使用服务端登录身份，服务层再按该身份过滤列表或核对订单归属。明确输入订单号、选中上一条候选、聊天 token 有效都只用于定位请求。猜到订单号无法改变身份。私人查询禁止跨请求共享响应缓存，代理不缓存私有 SSE。
5. 私有响应先完整校验并缓冲最少展示字段。发送第一条含订单事实的帧前再用同一凭证核对当前登录，覆盖在查询中途已撤销的情形。核对 401、超时或依赖异常均丢弃待发送数据。浏览器继续用会话代次过滤换号、退出或停止后的迟到帧；服务端检查对应请求处理时点，浏览器负责身份变化后清除已展示内容。同步 HTTP 取消后可到有界超时才结束，但不得续调或提交结果。

## 3. 选单、数据和错误

- 私有订单动作走确定性分支，先于普通对话图及 checkpointer，复用同会话互斥、查询预算和 SSE 关闭机制。显式指令支持「我的订单」「订单 123」「订单 123 的物流」，以及从订单模式继续「第二个」「下一页」「这单的物流」。无法唯一识别时请选单或明确订单号；首版提供订单入口，供自然语言未匹配时进入。订单模式和操作参数独立于商品候选；离开订单模式后「第二个／下一页」恢复商品语义。
- 最小状态为当前实际展示的订单 ID 顺序、上一页游标和 `hasMore`、一个已选 ID。首版在单 worker 进程内按聊天会话 ID 和已验证登录身份绑定，成功读或初次进入后暂存 15 分钟，最多 1024 个会话。新会话、登录变化和重启后重新查列表。取消或错误不提交新状态。每次成功新页整体替换候选，选单后重新查询并验证归属。末页 `hasMore=false` 且 `nextCursor=null`，后续不追加查询。不接受聊天文字指定分页游标。
- 订单场景的用户输入、凭证、候选、原始响应和渲染文字不进入模型、聊天记录数据库、checkpoint、摘要或追踪。私有结果只出现在当轮页面 DOM；不写浏览器存储。对显式订单请求或订单模式中无法解析的输入，留在私有分支澄清。普通聊天随手粘贴敏感内容的通用识别另属全局数据治理，首版在订单入口提示不要发送密码、验证码、地址或手机号。
- 展示白名单建议为订单编号、店名、状态、商品数及应付金额；详情增加商品名、规格与件数。现金应付与积分分别展示，100 个最小积分单位等于 1 积分。物流展示包裹状态、承运商、有值的发货及确认时间；运单号最多显示末四位，长度不超过四位时全掩码。收货人、电话、地址、内部优惠/评价等字段在适配器解析后丢弃。仅根据上游状态解释，空包裹列表显示「暂无包裹信息」，不推断必然未发货或预计送达。对没有时区的时间不补 UTC 偏移，签收、自动确认时限和整单收齐分别处理。
- 仅 `HTTP 200 + code=200 + 合法结构` 进入展示。列表游标、条目、详情 ID、包裹 ID、订单关联或金额不合法时整批停止展示，保留已脱敏的错误类别。404 的统一提示为「未查到可访问的订单」，他人订单与不存在用同一提示，不显示上游正文。400（含游标无效）提示重新选择，不自动重置重试。403 统一拒绝。429、5xx、网络超时或包络不符如实提示暂不可查询。只有有效 200 空数组才是无订单或无包裹。
- 上游在 SSE 开始后返回有效 401 时，返回新增的私有终止错误 `ORDER_AUTH_EXPIRED`，页面按身份变化清除旧订单结果、移除聊天 token，不自动重发原消息。保留原请求开始前的 401/409 区分。日志使用 request_id、接口模板、状态、耗时和是否取消等技术字段；不记订单号、游标、地址、运单、原始页面数据或凭据。
