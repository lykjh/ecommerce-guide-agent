## Agent 架构调整

原因：商品查询散落于节点，memory 混合商品参数和业务提示词；导入依赖即初始化向量库；对比重复抽取路由已确认的对象；异步查询被放到新事件循环。

- `agent/state.py` 保存图状态，`agent/tool/schemas.py` 保存商品筛选契约。持久状态字段和 SQLite 格式未改变。
- `memory.py` 只处理通用历史上下文和摘要；业务提示词归 prompts 和对应节点。
- `nodes/recommend.py` 独立承担推荐；商品查询统一经过 `tool/product.py`，节点不直接依赖检索器。
- `deps.py` 提供共享模型构造和按需客户端。导入节点不创建模型或 Chroma 连接。
- 对比消费 `route_subjects`，不再次调用模型抽取商品；缺少资料仍停止回答。
- 同步查询仍进线程且实际结束才释放名额；异步查询留在调用者事件循环，超时取消后释放名额。预算和查询日志保留。
- 图装配的业务节点清单同时生成输出白名单，新增节点无需额外维护两份名单。
- 测试用函数替身，不再替换 sys.modules；增加导入副作用、异步取消、对比、商品查询及推荐输出回归。

限制：本次是职责调整，未接入商城 HTTP API。静态推荐仍不是价格/颜色硬筛选，概览仍使用示例商品及本地计数；后续接商城时使用真实分页结果，不推断总数。未增加商城客户端空壳、缓存、自动重试或通用插件系统。节点状态必须来自路由；直接调用对比节点的诊断脚本需提供 route_subjects。

验证结果见本目录 architecture-tests.txt；未调用在线模型、未重建向量库。
