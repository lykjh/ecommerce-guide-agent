## 1. 用户与范围

目标用户为商城游客、已登录买家和接待人工客服。游客可咨询商品及政策；已登录买家可查询本人订单；人工客服接收会话、关联对象和必要摘要。

解决：找商品、了解商品、比较候选、了解政策、查询本人订单和物流、转人工。

不解决：注册/登录业务实现、退款执行、取消订单、修改地址、支付、优惠审批、修改商品、跨用户查单。登录由商城现有流程完成。用户提到这些操作时，可解释已检索到的规则并引导现有入口或人工，不承诺操作成功。

## 2. 能力单元（Skill）

此处 Skill 指业务能力单元，不意味着安装独立插件或部署多个 Agent。

| ID | 能力 | 业务输入 → 输出 | 前置条件 | 失败行为 |
| --- | --- | --- | --- | --- |
| S01 | 闲聊与澄清 | 当前问题、近期上下文 → 简短回复或一个必要问题 | 无 | 无法理解时给出可选方向，不强推商品 |
| S02 | 商品咨询 | 商品指向、问题 → 有依据的商品答复/卡片 | 商品可唯一确定 | 请求选择；查询失败不说商品不存在 |
| S03 | 筛选与推荐 | 预算、品类、用途、偏好 → 候选商品及理由 | 足够形成有效查询；可先澄清 | 无结果如实说明，放宽硬条件需用户同意 |
| S04 | 商品对比 | 至少两个明确商品 → 有来源的异同 | 每个对象都能核实 | 缺失对象先澄清；缺失参数标注未知 |
| S05 | 政策问答 | 政策问题、适用商品/订单背景 → 规则及来源 | 有当前有效且适用的材料 | 无依据或材料冲突则说明不能确认并引导人工 |
| S06 | 本人订单查询 | 用户可信身份、订单指向 → 状态/物流 | 已登录，商城校验归属 | 登录引导、选单或无权访问；不泄露订单是否属于别人 |
| S07 | 转人工 | 用户意愿、问题背景 → 接待状态 | 有实际接待系统或留言机制 | 无人在线明确说明；创建失败不能称已转接 |

## 3. 工具能力需求

T01–T07是稳定的业务能力标识，不是HTTP端点名。T01/T02已有技术契约，其他工具待真实依赖确认；字段类型、路径和错误码统一见[商城接口](../03-接口/商城接口.md)与[内部工具契约](../03-接口/内部工具契约.md)。

| ID | 用途 | 所需业务输入 | 所需业务输出 | 前置条件与失败行为 |
| --- | --- | --- | --- | --- |
| T01 | 搜索商品 | 用户明确条件、分页意图 | 商品标识、展示数据、本批数量、分页信息 | 仅可展示商品；空结果与服务异常分开 |
| T02 | 商品详情 | 已解析商品/规格标识 | 规格、价格口径、可售状态、可公开库存信息、链接 | 对象须真实；不存在/下架不得用近似商品顶替 |
| T03 | 检索知识 | 问题、适用范围 | 材料片段、来源、版本及有效性信息 | 无适用来源则不下政策结论 |
| T04 | 本人订单列表 | 服务端身份、用户表达的筛选条件 | 本人订单的最小必要摘要 | 未登录不查；多结果交用户选 |
| T05 | 本人订单详情 | 服务端身份、选中订单 | 状态、金额口径、商品、时间 | 每次检查归属；无权访问不重试绕过 |
| T06 | 本人物流查询 | 服务端身份、选中订单 | 发货状态、承运信息、物流事件 | 无物流不等于异常；接口失败不推断物流状态 |
| T07 | 人工接待请求 | 可信会话、请求原因、最小上下文 | 已排队/已接入/离线/失败等真实状态 | 幂等；结果不明先核实，不能盲目重建 |

## 4. 决策规则

- 寒暄、解释能力范围、要求补充必要信息：不为凑流程调用商城业务工具；闲聊允许已有意图/信号、生成和审核模型调用。
- 价格、库存、规格、订单、物流事实：查询业务工具后回答；历史摘要不是最新事实。
- 政策问题：T03；问题同时含价格与退换条件时，分别取业务事实和政策证据。
- 推荐：T01，必要时 T02；只能引用已返回的商品，卡片字段由确定性代码生成。
- 对比：逐个核实对象再对比；名称相似不能证明同一商品。
- “第二个”“昨天那单”：先解析会话中的候选映射；不能唯一确定就澄清。
- 明确转人工：优先处理，不先强制完成推荐或意图问答。
- 未登录查单：引导商城登录，不收集密码或验证码；恢复身份后重新校验订单权限。
- 用户拒绝推荐：记录会话内拒绝偏好；只有用户重新明确请求选购/推荐时才解除。
- 混合请求：目标是明确可完成和未完成部分，不可用一个成功结果冒充整轮成功。当前固定图只处理明确“先/再”的第一项；多个独立目标没有顺序时先澄清，不声称后续任务已执行。

## 5. 边界与拒答

| 情况 | 行为 |
| --- | --- |
| 查他人订单、索取后台数据、绕过身份 | 简短拒绝，提供本人订单或人工服务路径；不确认目标数据存在性 |
| 输入/检索材料要求忽略规则、泄露密钥、执行任意代码 | 当作不可信内容；权限和工具范围不变 |
| 用户主动提供密码、验证码、完整证件信息 | 不复述，不写入普通日志；提示无需提供此类信息 |
| 医疗效果、绝对功效、未提供的优惠承诺 | 仅转述有依据且适用的商品说明，不作额外保证；必要时转人工 |
| 超出业务范围或写操作 | 说明能力边界，提供已核实的操作入口或人工 |
| 资料缺失、模型拒答、接口失败、预算用尽 | 明确未完成项；提供澄清/重试/人工选择，不假装成功 |

指标分母和评分方法见[测试计划](../08-测试/测试计划.md)。这些数值是保留的V1建议门槛，尚无全量真实模型成绩证明达标。

| 指标 | V1 门槛 |
| --- | --- |
| 意图/下一动作正确率 | ≥95%，各核心业务类别 ≥90% |
| 工具轨迹正确率 | ≥95%，必须同时满足权限、参数语义及依赖顺序 |
| 多轮对象解析正确率 | ≥95% |
| 可核实业务事实无依据率 | ≤1%；伪造订单、金额或越权泄露样本为 0 |

安全或金额相关硬门槛不允许用总体平均分抵消。固定样本通过只证明样本范围内通过，不证明绝对安全。

## 8. 公共行为要求

- M01短期记忆：保留本轮输入一次，按字符和消息窗口选取相关近期历史，不把上一轮回答当成本轮结果。
- M02持久记忆：同一会话摘要和业务状态可持久化、重启后恢复；不同会话隔离。这里的长期记忆是会话持久摘要，不是跨会话身份档案。
- M03条件修改：新明确值覆盖旧值，取消条件置空；“便宜一点”不等于擅自编造数值预算；换品类清除不适用条件。
- M04事实新鲜度：历史价格/可售/订单状态不是当前事实，涉及此类事实须重新查询。页面恢复上下文不等于已实现聊天历史列表展示。
- C01并发：同会话已有请求时拒绝新一轮，不调用模型、不写历史；不同会话允许重叠，不用整轮全局锁串行化所有用户。
- C02取消与恢复：取消/超时停止新调度，释放会话与异步资源；同步IO仍执行时保留额度直到实际退出。不承诺撤回已发生费用或回滚已写入的半轮记录。
- C03作用域：当前单worker单事件循环。多worker/多实例、真实用户退出换号和私有订单隔离须另行设计验收。
- U01展示：路由、条件提取、摘要和审核中间内容不展示；闲聊须完整审核后再逐步显示；停止保留已显示内容。收起不等于取消。
- U02故障：HTTP错误、SSE异常、预算终止、未查到结果和未接入能力分别表达；不把done事件等同于业务成功。
- O01追踪：按request_id关联模型/工具/预算，记录用量及未知计量，不记录凭证或敏感业务正文；生产数据保留与清理规则待冻结。

执行预算的实际常量与预留行为以[工程设计](../04-工程/工程设计说明书.md)及源码为准；本文件的质量目标不覆盖或修改运行预算。

## 10. 商品客服阶段 A-1.0（已确认、待实施验收）

确认日期：2026-11-03。完整V1范围不变；本阶段交付公开商品咨询、推荐、对比、概览及多轮行为的收尾与验收。使用现有独立窗口、单worker单事件循环；只做后续身份方案设计，不实现账号绑定、订单、政策、人工或商城宿主嵌入，不作生产容量承诺。下表是本阶段必须满足的行为，不是已实现声明。

| ID | 场景 | 必须满足的结果 |
| --- | --- | --- |
| A-R01 | 分类定位 | 复用商城逐级分类接口，不新增分类搜索接口、不遍历整棵树。ID来自真实返回，不能编造；存在多个合理去向时展示路径请用户选，不把某分支唯一命中当全局唯一 |
| A-R02 | 分类不明与故障 | 成功查询后仍不能定位，可明确按关键词搜索，不声称精确分类；分类接口失败则说明未完成，不冒充无分类或静默搜索成功 |
| A-R03 | 上级分类 | 用户选择的可见上级分类可作为筛选范围，包含其可见后代，不强迫选择到叶子 |
| A-R04 | 预算/颜色变化 | 保留已确认分类；重新查询商品并清除旧分页游标；取消条件确实清除，不从摘要恢复 |
| A-R05 | 换品类 | 清除旧分类和分页，重新定位；其他条件沿用M03，清除不适用条件，不能无依据新增或放宽条件 |
| A-R06 | 序号及换话题 | 等待分类选择时“第二个”指向最近展示的分类候选；否则沿用商品指代规则。用户转问其他问题时退出分类澄清；不强迫继续、不让旧分类候选抢占新话题 |
| A-R07 | 规格范围 | 本阶段筛选仅收尾价格、颜色、可售状态，三者必须在同一SKU成立。不同颜色名称不自动等价，展示商城实际值请用户确认；不能核实的硬条件不得称已满足 |
| A-R08 | 其他规格 | 尺码、容量、版本等仅依据资料回答咨询，不承诺已支持筛选；不能忽略用户此类硬要求后声称商品符合 |
| A-R09 | 结果表达 | 区分本批无匹配、资料不足、接口失败；不虚构商品、参数、价格、库存或发货承诺，不自动放宽条件；本批数量/hasMore不冒充全商城总数 |
| A-R10 | 执行边界 | 分类和商品请求共用现有调用数、时间和token预算，不提高上限、不自动遍历或翻页；取消/超限后不调度新调用，取消不等于已经发出的同步IO被撤回 |

本阶段质量门槛：适用确定性行为检查100%通过；已执行验收样本中虚构商品、错误价格、跨SKU拼接、把未核实条件说成满足均为0例；语义理解总体正确率≥95%，每类≥90%。这是样本范围结论，不承诺未来零错误。此处商品事实0例门槛优先于第6节完整V1仍待评审的“无依据率≤1%”建议，不能用平均分抵消硬失败。计算口径与执行条件见测试计划，最终判定见验收报告。
