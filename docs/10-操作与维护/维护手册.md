## 1. 环境与启动

在项目根目录运行，不在agent目录直接启动脚本。现有依赖文件以Python 3.14.0环境整理，直接依赖锁定在[requirements.txt](../../requirements.txt)；使用已有`.venv`。首次建环境或依赖缺失时才安装，不为日常重启重新升级依赖。UI回归通过Python包装调用Node.js，测试环境需能执行`node`；历史验证使用Node 24.19.0，不表示自动安装了Node。

```powershell
Set-Location 'D:\desktop\PythonProject'
.\.venv\Scripts\python.exe -B -X utf8 -m uvicorn agent.http_api:app --host 127.0.0.1 --port 8000 --workers 1
```

启动前将AGENT_PUBLIC_ORIGIN设为浏览器实际使用的origin。本节用127.0.0.1时应设置http://127.0.0.1:8000；.env.example中的http://localhost:8000是另一个origin，不能混用。缺配置POST返回503，来源不匹配返回403。浏览器访问`http://127.0.0.1:8000/`。开发默认只监听本机，当前不采用Streamlit。若8000已被其他项目占用，保留其他服务并把本服务端口改为8001：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m uvicorn agent.http_api:app --host 127.0.0.1 --port 8001 --workers 1
```

切到8001时同步将AGENT_PUBLIC_ORIGIN改为http://127.0.0.1:8001；随后所有浏览器、health、OpenAPI检查都使用8001。不能仅因8000返回HTTP 200就认定命中了本项目。读取`/openapi.json`确认`info.title`为“电商客服 Agent”，并含`/api/sessions`和`/api/chat`；`/health`只证明进程可响应，不验证模型余额、商城、数据库恢复、订单或人工服务。

```powershell
$agentBase = 'http://127.0.0.1:8001'
Invoke-RestMethod "$agentBase/health"
$agentSpec = Invoke-RestMethod "$agentBase/openapi.json"
$agentSpec.info.title
$agentSpec.paths.PSObject.Properties.Name
```

当前使用单worker、单事件循环。不要加`--workers 2`或让多个独立Agent进程写同一SQLite，再把锁错误当作已支持场景。未配置系统服务、开机启动或部署编排；需部署时另行确定进程管理、HTTPS/反向代理、身份接入、跨域与限流。代理如缓冲SSE会破坏及时显示，部署验收须验证增量与断连取消。

## 2. 配置、凭证与变更

| 配置入口 | 当前作用 | 运维要求 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 模型调用凭证 | 放受保护环境变量或根目录.env，不能写入源码/日志/报告 |
| `OPENAI_BASE_URL` | OpenAI兼容服务地址 | 真实地址可能包含租户信息，不在公开文档复制 |
| `AGENT_SESSION_SECRET` | 会话HMAC密钥，至少32字符 | 使用稳定随机密钥并保密；不要每次启动生成新值 |
| `AGENT_PUBLIC_ORIGIN` | 两个POST入口的唯一可信浏览器origin | 精确scheme://host[:port]，无路径；浏览器域名、协议、端口变化时同步更新并重启 |
| `MALL_BASE_URL` | 商城根地址 | 当前开发示例`http://127.0.0.1:8080`；不加`/users/csrf`等接口后缀 |
| `config/app.yml: path.db` | SQLite checkpoint路径 | 默认项目根`chat_memory.db`；相对路径按项目根解析 |
| `llm.model/router_model/signal_model` | 主模型/路由与提取/信号模型 | 当前统一qwen3.6-flash；摘要复用router_model；修改后需重启服务 |
| `llm.extra_body` | 当前enable_thinking=false | 换模型先核对兼容性，不能不加区分套用于所有模型 |
| `llm.max_tokens` | 当前普通调用配置1024 | 路由另用256，摘要600，预算另有限制；不要只调大输出掩盖推理占额 |
| `mall.base_url_env`及`llm.*_env` | 读取环境变量的名字 | 改实际环境值或变量名时保持一致 |

配置文件和模型客户端有进程内缓存；改完配置正常停止并重启后生效。不要在不知情时覆盖已有.env或把完整环境打印到终端。当前根`.env`由python-dotenv加载；若同时设置系统/进程环境，核对实际读取来源，排查时只报告是否设置和脱敏指纹，不复制值。

签名密钥是匿名会话持续可用的条件。轮换后旧session_token失效，需要新建会话；这不会自动删除旧数据库记录。它不是商城登录密钥，也不产生用户订单权限。恢复历史会话需要原数据库与原签名密钥一致；任何需要更换安全策略的动作单独评估，不能为了方便对外公布令牌。

## 3. 停止、重启与取消

前台启动的服务在所属终端按Ctrl+C，等待Uvicorn正常退出；确认没有该服务仍在写库后再备份/升级。只停止确认属于本项目的进程，不批量结束所有python或占用8000的未知程序。以进程PID排障时同时核对命令行和工作目录。

用户停止回复或断开页面会取消该请求，回收图执行、SSE与会话占用。同步商城HTTP已进入线程后不能保证立即被终止，日志可能先出现`timeout_background_pending`/`cancelled_background_pending`，工具槽到线程真实结束才释放。不要把停止按钮理解为上游操作回滚或模型费用退还。重启中断的答复也不承诺自动续传，用户须重新发送。

页面的收起与新建会话含义见用户手册。收起窗口不是清理会话数据库；需要数据删除时先确定保留与删除策略，不能把前端清空等同于合规删除。

## 4. 日志与日常排查

日志目录为项目根`logs/`。文件默认`<logger>_YYYY-MM-DD.log`，日期在创建handler时确定；当前不是跨午夜自动切换/自动清理的轮转器。保留期限、容量告警和日志平台尚未配置完成，应按明确运维策略管理，不能删除正在使用的日志来“修复”业务。

先定位页面/SSE的request_id，再关联`http_*`、`turn_usage`、`llm_usage`、`budget_*`、`query_finish`、`mall_request`。同一会话多轮需要区分request_id；会话标记不能充当商城用户身份。

| 观察点 | 正确解读 |
| --- | --- |
| `llm_usage` | stage、input/output/reasoning_tokens、finish_reason、usage_known、duration_ms |
| `turn_usage` | 多阶段合计；unknown_usage/unfinished意味着统计不完整，不能按0计费 |
| `budget_stop reason=...` | 区分model_calls/tokens/single_call_tokens/repair_calls、query_calls/query_busy、模型/查询超时、deadline、cancelled |
| `query_finish` | completed/failed/timeout/cancelled及后台待结束状态；不等于SQL数量 |
| `mall_request` | 端点模板、HTTP/业务状态与耗时；不要附完整敏感请求值 |
| `http_finish outcome=completed` | SSE正常结束，可能只是忙提示/预算停止；不是问题已解决的证明 |
| `summary_skip`或摘要失败 | 保留原文，不自动把失败摘要当新记忆；持续出现会影响体积与上下文预算 |

已知用量不包含完整embedding费用，金额还需模型单价/计费口径；免费余额不能由token日志推算。正常离线测试会主动制造超时、坏JSON、budget_stop等日志，是否通过看退出码和最终unittest结果，不凭日志中出现“失败”两字下结论。

排障报告至少记录时间、版本、request_id、场景、现象、最小复现、预期/实际、错误类型、修复及验证结果，放入[每日问题记录目录](../06-问题发现与解决/)。避免记录完整用户对话、Prompt、Authorization/Cookie/Key、订单隐私；受控采样另行脱敏并限定留存。不要认为会话原文已因“日志没有打印”而从SQLite删除。

## 5. 常见故障定位

| 现象 | 先检查 | 处置与边界 |
| --- | --- | --- |
| 请求404或前端无法读取message | OpenAPI标题/路径、当前端口、请求路径 | 8000可能是其他FastAPI；本Agent改8001并访问同源页面，不靠补重复异常兜底解决错服务 |
| 401 INVALID_SESSION | 是否持有本服务令牌、密钥是否轮换 | 新建会话；不使用任意thread_id绕过签名 |
| 503 CONFIGURATION_ERROR | AGENT_SESSION_SECRET是否满足长度、进程实际环境 | 设置稳定密钥后重启；不打印密钥 |
| 模型余额/权限/模型不存在 | 服务商返回的状态与脱敏错误、配置模型名 | 按第7节切换候选并做定向验证；不无条件循环换模型 |
| 路由JSON截断、finish_reason=length | 256上限、reasoning_tokens、enable_thinking是否生效 | 历史原因包括推理消耗输出预算；先确认无推理设置和schema支持，不能直接认定额度耗尽 |
| 本轮处理停止 | budget_stop具体reason及整轮各阶段耗时 | 根据预算/慢请求定位；不要默认都是没余额，也不无依据提高所有上限 |
| 商城503/搜索不可用 | mall_request和商城自身服务/索引状态 | 如实提示未完成；模型/假商品不能代替失败查询 |
| 无结果或颜色未知 | 同SKU条件、响应选项、当前页范围 | 合法无匹配不是接口故障；不放宽用户条件或编造总数 |
| SQLite locked | 是否多进程/多loop共用DB、旧服务残留、正在备份/写入 | 支持边界内复现并保留日志；不要删除数据库或擅加大段自动重试 |
| 页面等整段审核后才逐步显示 | 当前是否闲聊路径 | 用户选择保留审核：这是预期；不是每个字符重新调模型 |
| 切模型/改地址后似乎未生效 | 当前进程是否重启、环境值是否被旧进程继承 | 正常重启并重新确认；配置/客户端有缓存 |

新问题遵守工程G01–G07。模型解析边界需要一次结构校验，但不能因模型不确定就每层重复判空；只在明确边界处理具体异常，不能全图catch后吞错。

## 6. SQLite一致性备份与恢复

当前默认数据库保存checkpoint和会话原文/摘要；不是无敏感信息的缓存。没有已验收的自动备份、到期删除或跨版本迁移流程。备份文件与恢复测试需受访问控制。

推荐受控停机备份步骤：

1. 停止接纳新请求，结束本项目所有写入进程及诊断脚本，等待在途请求/线程结束。确认真实`path.db`，不要只依据默认文件名。
2. 在停止写入的状态使用SQLite backup API导出独立快照。不要在写入/WAL活动中只复制`.db`并忽略WAL；也不要从不同时间点拼接db/wal/shm。
3. 校验备份`integrity_check`，记录代码/配置/依赖版本与时间；单独保管恢复所需的原签名密钥，不能把明文密钥打进普通文档/证据包。
4. 备份确认后再启动服务；保留一个经过验证的先前版本。保留周期、加密与异地位置待运维要求确定。

以下示例仅在已停写、确认实际路径后执行；创建时间戳新文件，不覆盖旧备份。SQLite backup API会把读取到的完整数据库状态复制到单个目标文件，无需手工拼接WAL：

```powershell
Set-Location 'D:\desktop\PythonProject'
@'
from datetime import datetime
from pathlib import Path
import sqlite3
from agent.utils.config_tool import get_app_config

source = Path(get_app_config().abs_path('path.db')).resolve()
target_dir = Path('backups')
target_dir.mkdir(exist_ok=True)
target = target_dir / ('chat_memory-' + datetime.now().strftime('%Y%m%d-%H%M%S-%f') + '.db')
with sqlite3.connect(source.as_uri() + '?mode=ro', uri=True) as src:
    with sqlite3.connect(target) as dst:
        src.backup(dst)
        result = dst.execute('PRAGMA integrity_check').fetchone()[0]
        if result != 'ok':
            raise RuntimeError('Backup integrity check failed')
print(target.resolve())
'@ | .\.venv\Scripts\python.exe -B -X utf8 -
```

恢复前同样停止所有写入，先完整保存当前db及仍存在的对应wal/shm作为一个故障现场；不要直接覆盖正在使用的db，也不要让旧WAL混入新快照。将已校验快照恢复到确认的`path.db`，保证该目标没有不匹配的旧伴随文件。以匹配版本代码/配置和**原AGENT_SESSION_SECRET**启动；若主动轮换密钥，则明确旧令牌不可再访问，不假称原会话可恢复。

先在隔离副本上验证SQLite完整性和同会话读取，再做业务恢复验证；模型续聊可能产生费用，按已授权测试范围进行。`integrity_check=ok`只证明数据库结构一致，不证明应用schema兼容、摘要完整或跨用户授权正确。若恢复版本不兼容，不自动添加旧memory兼容分支，记录并确定迁移方案。

## 7. 模型切换与额度

用户已授权模型不可用时更换候选，无需再次申请切换，也无需先逐个探测或把重新评测作为切换前置条件；该授权不等于软件已经实现自动轮换。当前仍由配置选择固定模型，不会遇到429/超时就后台轮流试28个候选。切换流程：

1. 用实际错误区分额度/权限、模型名、参数不兼容、超时、JSON截断；保留脱敏证据。
2. 从历史候选或服务商已确认列表选适合任务的模型。OCR、翻译、专用意图模型不直接假定支持普通聊天、工具或当前JSON schema。
3. 只改需要的`llm.model/router_model/signal_model`；若供应商改变，核对协议地址、凭证、extra_body、结构输出、推理开关和usage语义。不要把密钥写进yml。
4. 正常重启；需验证行为时，按已授权范围选择关联离线用例和少量真实调用：正常路由、JSON有效性、预算修改/取消、答复证据、token和finish_reason。用户明确不测试的任务不额外探测。记录实际验证情况，不沿用旧模型评测结论；未测不虚报通过。
5. 失败则回到先前可用配置或明确停止该能力；不要增加未经确认的自动fallback、无限重试或付费扩容。
