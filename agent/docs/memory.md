# 会话记忆实现说明

状态：2026-11-01 已实现会话内短期窗口和持久摘要；已完成小样本真实模型冒烟测试，尚未完成全量评测。

## 已实现

- 短期记忆：最多最近 8 条消息、正文合计 6000 字符，整条选择并从用户消息开始，不依赖商品关键词判断是否需要历史。裁剪边界可能使实际条数少于 8。
- 长期记忆：超过窗口的旧消息与已有摘要合并，摘要最多 1200 字符。它随 thread_id 保存在现有 SQLite checkpoint 中；同一 ID 可恢复，不同 ID 隔离，不是跨会话用户画像。
- 每轮最多一次摘要调用，10 秒超时，不自动重试；输入旧消息最多 32 条、正文合计 12000 字符，另带旧摘要及提示词。只有摘要有效才在同一状态更新中删除已摘要消息。
- 摘要失败、超时、为空或超长时保留旧摘要和原消息；下一轮继续尝试有界批次。输出给业务模型的历史窗口仍有界。
- 路由、信号判断、咨询、闲聊、推荐、筛选抽取和对比抽取统一使用该窗口与摘要。摘要作为历史数据传递，明确不能当作当前价格、库存或订单依据。
- 摘要模型按需初始化，内部调用标记为 internal；模型替身可直接注入测试，不需要网络、Key 或商品向量库。

## 使用与边界

调用 get_ai_stream 时传入稳定且隔离的 thread_id。现有 Streamlit 新会话会生成新 ID，因此刷新/新建聊天不自动恢复旧 ID；恢复已有会话须由调用方保留并传回原 ID。接口的默认 ID 仅兼容本地示例，商城接入时必须显式传入已鉴权的会话 ID，不能把 thread_id 本身当作身份凭证。

用户输入非空且不超过 6000 字符；字符上限是本次实现的确定性限制，不是精确 token 计量。全请求 token/时间预算尚未实现，不能把摘要的局部超时当作完整执行预算。

摘要是有损压缩，准确性与敏感内容排除目前依赖提示词，尚无完整数据脱敏层；不要用它存放凭据或代替结构化订单权限状态。持续摘要故障时，为避免数据丢失，checkpoint 中的未摘要原文会积累；旧 checkpoint 历史也不会因 RemoveMessage 自动从数据库物理删除。存储保留/清理与监控仍需后续实现。

本次保留既有 signal_state 与业务逻辑，不包含同会话并发串行化、商城身份绑定、长期用户画像或商品检索查询改写。同一会话调用需由上层串行处理。

## 离线验证

在 agent 目录执行：

```powershell
..\.venv\Scripts\python.exe -B -m unittest discover -s tests -p 'test_memory.py' -v
```

覆盖窗口、摘要增量删除、失败恢复、无效摘要、超时与取消、字符/批次上限，以及真实 SQLite 文件关闭重开后的恢复和 thread_id 隔离。SQLite 测试使用 tests 下独立临时文件，结束后删除，不打开现有 chat_memory.db。模型使用固定替身；不代表真实模型的摘要质量已验收。

## 真实模型冒烟测试

显式执行（需要网络与已配置模型凭据，会产生调用费用；不随离线 unittest 自动运行）：

```powershell
..\.venv\Scripts\python.exe -B -X utf8 tests\live_memory.py
```

使用项目配置的 qwen-flash 生成摘要、qwen-plus 回答恢复后的追问；数据全部虚构，SQLite 使用独立临时文件。最近一次结果见 [测试报告](memory-live-result.json)，脚本重跑会覆盖该报告。

2026-11-01：偏好摘要、偏好修正、历史不可信内容过滤、SQLite 重开恢复及新会话隔离、恢复后的模型追问共 5 项检查通过。初次在线运行发现恶意指令文字被复述进摘要，已补充禁止记录指令和处理说明的提示词，并整组复测通过。

这些检查使用固定关键词和状态断言，不是完整语义裁判；例如回答中增加的解释未做逐句事实评审。单次小样本通过不证明普遍防注入或敏感信息过滤可靠，也不覆盖完整商城工具链、UI 或多用户并发。
