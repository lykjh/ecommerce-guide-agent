# 电商客服 Agent 开工文档

版本：0.1.0｜日期：2026-11-01｜状态：需求与设计初稿，待评审

本目录定义计划建设的行为，不代表现有代码已经实现或验收通过。本轮仅产出文档，不修改业务代码。目标商城为自建商城，第一版范围为商品咨询、导购、本人订单查询、转人工。

用户要求商城接口稍后补充：本轮不确定接口路径、HTTP 方法、函数签名、请求/响应 schema、鉴权协议或业务错误码映射。文中的能力名称与业务输入输出只是行为要求，不是接口契约。

## 已确认与待确认

- 已确认：自建商城；商品咨询、导购、本人订单查询、转人工；先写文档，不开发。
- 已确认细化范围：商品咨询、筛选推荐、商品对比、政策问答、本人订单查询、转人工；数据边界获认可。下游调用预算、独立并发限制、数据库影响测试纳入上线门槛。
- 设计建议：保留 LangGraph 单 Agent，固定业务流程加有限工具循环；模型不承担权限判断。
- 待评审：指标目标、预算阈值、人工服务流程、数据保留周期和生产存储选择。
- 待提供：商城接口与身份体系、商品及订单字段、客服接待能力、模型部署与计费信息。

## 当前项目基线

依据本次会话的源码阅读：已有 LangGraph 路由、咨询/闲聊/筛选/对比/推荐节点、Chroma 检索、SQLite checkpoint 和 Streamlit 页面。筛选仍使用 4 条 Mock 商品；订单与人工接管尚未接入。已有摘要不裁剪消息；推荐名称片段匹配不能证明商品身份。本文的目标设计不能当作这些问题已经修复。

## 开发门槛

1. 确认 01 中的范围与拒答规则。
2. 补齐 07 的商城和人工接待信息，再形成工具接口契约。
3. 评审 02 的信任边界及 06 的预算，确定生产运行约束。
4. 将首批用例转为固定 fixture 和可执行测试，保留独立验收样本。
5. 核心 Prompt 与评测版本一起冻结后进入实现。

上线另须通过 04 中 DB01–DB06 数据库影响验收，并补齐 06 的下游容量阈值；文档中的初始建议值不代表商城已具备对应承载能力。

文档写完不等于以上门槛已通过，也不构成编码授权。

后续实施记录：用户已授权先实现短期记忆与同一会话持久摘要，详见 [记忆实现说明](../memory.md)。仅该子任务进入实现，不代表其他规划已落地或生产门槛已通过。
