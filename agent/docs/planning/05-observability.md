# 可观测性与追踪方案

版本：0.1.0｜状态：待评审，尚未埋点

## 1. Trace 结构

一次用户请求对应一条根 trace；多轮通过会话关联，不把整段会话做成永不结束的 span。

```text
request
  ├─ identity_and_session_check
  ├─ state_load
  ├─ routing / extraction (可含 llm span)
  ├─ decision_round[n]
  │    ├─ budget_and_policy_check
  │    ├─ tool_call (每次尝试单独 span)
  │    │    └─ downstream / retrieval
  │    └─ result_validation
  ├─ answer_generation / answer_validation
  ├─ optional_repair
  └─ state_save / response_end
```

工具重试记录独立 attempt，并关联同一逻辑调用。超时、用户取消、断线、拒绝、人工接管也必须闭合 trace；中间进度输出不标记业务完成。

## 2. 字段要求

公共字段：trace_id、span_id、parent_span_id、request_id、会话脱敏标识、主体脱敏标识、时间、服务环境/版本、stage、duration_ms、outcome、reason、error_family。

LLM：模型部署标识、生成参数版本、Prompt ID/version/hash、attempt、输入/输出 token、token 来源（供应商/估计/未知）、终止原因、成本估计及计费版本。

工具：能力 ID、逻辑调用标识、attempt、规范化参数指纹、cache_hit、结果分类、记录数量、重试原因、剩余预算、下游 correlation ID。指纹需使用受控 HMAC 或等效方式，不能对低熵手机号直接裸 hash 后认为已匿名。

RAG：资料 ID/版本、检索配置版本、候选/保留数量、距离或评分名称、无结果原因。默认不记录原始文档正文。

运行指标标签仅使用低基数维度，如 stage、工具类别、结果类别、模型配置版本。用户 ID、会话 ID、订单号不能作为指标标签。

## 3. 结果分类

根请求结果枚举为监控语义，不是对外错误码：

- success：本轮目标全部完成。
- clarification / needs_login / policy_denied：预期业务分支，不计技术错误。
- no_match：成功查询但无结果，不计技术错误。
- partial：部分目标完成，必须附未完成原因。
- handoff_queued / handoff_active / handoff_offline：真实人工状态。
- degraded：预算耗尽、模型不可用等导致降级。
- failed：请求无法提供预期服务。
- cancelled：用户取消或连接取消，单独统计。

分类不掩盖错误：部分回复已发出但物流超时，根结果是 partial，工具 timeout 仍计失败。授权拒绝是预期结果；权限校验服务故障属于技术错误，不能记为正常拒绝。

## 4. 指标与初始告警

以下阈值为试运行建议，需业务及运维评审；不表示已经配置监控。

| 指标 | 定义 | 初始规则 |
| --- | --- | --- |
| 请求技术影响率 | 因技术故障产生 failed/partial/degraded 的请求 / 已接纳且非取消请求 | 5 分钟 ≥20 请求且 >5%，告警 |
| 工具最终失败率 | 重试后仍技术失败的逻辑调用 / 逻辑调用总数 | 5 分钟 ≥20 次且 >5%，告警；尝试级错误另报 |
| 模型失败率 | 技术失败的模型尝试 / 模型尝试 | 5 分钟 ≥20 次且 >5%，告警 |
| 整轮耗时 | 根请求耗时 p50/p95，正常和降级分组 | 5 分钟 ≥20 次且正常完成 p95 >20 秒，告警 |
| 预算耗尽率 | 因执行预算终止的请求 / 已接纳请求 | 15 分钟 ≥20 次且 >5%，告警 |
| 人工创建失败率 | 无法确认或失败的创建 / 人工创建请求 | 连续 3 次失败告警；离线不计技术失败 |
| 安全事件 | 已确认泄露、跨用户状态、越权成功 | 任一事件立即告警并启动人工排查 |
| 费用 | 按供应商 usage 和价格版本估算并对账 | 金额阈值待补；达到日限额 80% 提示、100% 停止新的付费调度 |

低流量窗口不足样本时显示数据不足，不显示健康保证。等待人工时长单独统计，其服务等级待人工团队确认。

告警附脱敏 trace 引用、影响范围和退出原因。技术指标恢复后再恢复自动能力，不能自动无限重试。紧急开关应允许停止模型付费调用并保留人工入口。

## 5. 脱敏与保留

普通日志默认不记录原始 query、完整 Prompt、完整回答、工具 payload、消息历史、认证头。禁止记录密码、验证码、密钥、完整手机号、详细地址、证件信息、完整支付信息。

确有排障需要时，使用受限的抽样诊断存储：显式授权、字段白名单、入库前脱敏、访问审计、到期删除。先做字段级最小化，再对自由文本脱敏；正则匹配不是全部保障。脱敏失败时丢弃内容，只留失败元数据。

对话业务存储与普通日志分开授权，不因禁写日志而默认删除客服必需记录。保留期限、删除流程和审计要求待业务确认；生产上线前必须补齐并验证到期清理。评测报告也遵守同样规则。

## 6. 监控验收

用固定 trace 测试：所有模型/工具尝试都有 span；父子关系正确；使用量含重试；预期拒绝不计技术错误；超时仍计工具失败；cache_hit 不算下游调用；取消必结束；日志中不出现植入的手机号、密码或 Key。告警测试使用可控时钟和固定窗口，不靠真实等候触发。

## 7. 商城与数据库负载关联

区分记录每轮工具尝试数、实际商城请求数、缓存复用数，以及下游在途数、速率限额拒绝数、并发满额数和等待耗时。调用链传递可核实的 correlation ID，由商城侧关联接口耗时、SQL 数量/耗时、慢查询和连接池等待；Agent 无法取得的 SQL 指标标为未知，不能从工具次数推算成实测值。

商城商品浏览和下单的 p95/错误率，与数据库 CPU、I/O、连接数及锁等待一起观测。告警阈值与数据库影响验收采用同一组经评审的 SLO 和安全水位，数值待基线测试补充。超过阈值时应可暂停 Agent 商城查询入口，保留真实可用的人工或留言路径；不能为客服查询牺牲核心交易。
