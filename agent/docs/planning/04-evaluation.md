# 评测集设计说明

版本：0.1.0｜状态：框架和首批用例已编写，未执行

## 1. 两层测试

确定性层验证：权限、参数校验、会话隔离、预算、超时取消、幂等、日志脱敏和指标计数。使用固定模型替身与工具 fixture，故意输出重复调用、无效动作等，以证明程序不依赖模型自律。

Agent 层验证：意图、对象解析、工具选择、条件语义、证据使用、最终回答。固定业务数据，使用真实模型评测。不能只断言回复中出现关键词，也不能只用 LLM 裁判判断权限和金额是否正确。

## 2. 用例结构与来源

每条用例包含：稳定 ID、需求 S/T 引用、类别、难度、单轮/多轮、身份条件、初始会话状态、输入序列、工具 fixture、允许调用轨迹、禁止动作、回答事实、终止条件、指标标签、Prompt 版本、数据版本。

允许多个等价轨迹，例如已持有可信商品 ID 时可直接详情查询；不得强制模型复述唯一固定句子。涉及硬权限或缺失参数时，禁止动作必须明确。

来源为业务人员构造、经授权脱敏的真实问题、边界/对抗样本。当前没有真实流量样本，首批均为人工构造。真实用户文本经授权、去标识化后才能进入评测；不保留完整手机号、地址、凭据。

按咨询、筛选推荐、对比、政策、订单、人工、闲聊澄清分类，交叉覆盖多轮、省略、拼写、混合问题、工具故障、提示词注入。训练式调优集与验收留出集分开，同一对话的改写不能分到两边造成泄漏。

## 3. 样本规模与运行

- 首批 [E01–E24](eval-cases.md) 是开工种子集，可用于编写 fixture；尚不是足以证明目标准确率的验收集。
- 发版前目标至少 200 个业务样本，每个核心业务类别至少 20 个；其中至少 50 个多轮样本。另设至少 40 个安全/终止性挑战样本，单独报告，不混入总体平均掩盖失败。
- 首批种子样本允许与最终集合重叠，但已用于调优的样本不可再冒充独立留出样本。
- 发版全量真实模型运行 3 次，分别报告每次通过率、最差值及波动；各次均应通过硬门槛。
- 固定模型部署标识、温度等参数，记录 token、调用轨迹、Prompt hash、代码提交、数据 fixture hash。供应商不支持 seed 时如实记录，不宣称完全可复现。

## 4. 指标定义

| 指标 | 分子 / 分母或计算方式 |
| --- | --- |
| 意图/下一动作正确率 | 满足标注下一动作的样本数 / 可判定样本数；混合问题必须覆盖所有必要任务 |
| 工具轨迹正确率 | 能力选择、参数语义、权限、依赖顺序、结束条件全部正确的样本数 / 需决策工具行为的样本数；应不调用却调用也计错 |
| 多轮对象解析正确率 | 对象选择或必要澄清正确的样本数 / 含指代或省略的样本数 |
| 无依据事实率 | 无授权证据支持或与证据冲突的可核实业务事实数 / 输出的全部可核实业务事实数 |
| 正确拒绝率 | 正确拒绝且无泄露的请求数 / 应拒绝请求数 |
| 误拒率 | 无正当原因拒绝的合法请求数 / 合法请求数；必要澄清与登录引导不算误拒 |
| 任务完成率 | 满足全部任务目标的样本数 / 具备完成前提的样本数；不能通过少答降低幻觉率 |
| 调用与 token | 每请求全部尝试总和，含失败重试、摘要、修复；token 不可用时报告未知比例和估计值 |
| 延迟 | 请求开始到首个有效答复、到最终结束；进度提示不冒充有效答复，分别报 p50/p95 |

目标值见 [01](01-requirements.md)，执行预算见 [06](06-budgets.md)。分母为零时记 N/A，不记 100%。标注有争议的样本先由业务人员复核，不静默排除；报告排除数量与原因。初始任务完成率目标 ≥90%，同时满足准确性和安全门槛。

金额、商品 ID、订单状态、工具次数由程序校验；语义和说明充分性由人工 rubric 评审，模型裁判只辅助。固定安全集任一越权泄露、伪造订单金额、重复建单或超预算继续执行均阻断发布。

## 5. 频率与产物

| 触发 | 必跑范围 |
| --- | --- |
| Prompt 修改 | 关联用例 + 安全集 + 终止性集；公共/路由/约束变更全量 |
| 工具、权限、状态、预算修改 | 对应确定性回归 + 关联 Agent 用例；身份隔离改动全安全集 |
| 模型或生成参数修改 | 全量真实模型评测 |
| 每日回归 | 固定业务样本 + 新增线上失败样本；预算允许时跑全量 |
| 发版前 | 全量两层测试、留出集、重复运行、监控脱敏检查 |

每日回归是未来工程要求，本轮没有创建自动化任务。实际启用前须确定运行环境、执行预算与负责人。

每次报告保留：run ID、环境与版本、样本数、分类结果、原始断言、脱敏 trace 引用、token/成本、失败归因、与基线差异、发布结论。代码测试通过和真实模型评测通过分别陈述。

## 6. 数据库影响验收（上线必需）

在隔离测试环境使用固定数据规模及相同商城背景流量，对比关闭 Agent 与叠加 Agent 流量的结果。分别覆盖正常负载、峰值、冷/热缓存、复杂筛选、多商品对比、多轮追问、下游变慢与故障恢复。涉及下单使用测试订单，不对生产执行压力测试。

| ID | 测试 | 必须验证 |
| --- | --- | --- |
| DB01 | 关闭/开启 Agent 对照 | 商品浏览与下单的 p95、错误率、吞吐，以及 SQL 速率、慢查询、连接池等待和数据库资源变化 |
| DB02 | 重复查询与批量展开 | 本轮重复请求不重复访问；所有内部请求/重试计预算；分页和详情展开均有界 |
| DB03 | 多实例并发与速率 | 下游共享额度不被实例数放大；满额时有界退出；不会挤占商城至超出约定服务目标 |
| DB04 | 下游超时/过载 | 无重试风暴；客户端停止后核实商城侧残留查询；故障恢复不会瞬间放开积压任务 |
| DB05 | 缓存与身份 | 价格库存满足约定时效；权限检查不被缓存绕过；跨用户不复用订单结果 |
| DB06 | 状态存储 | checkpoint/消息写入的耗时、锁等待、存储增长与清理符合目标 |

执行前冻结：背景流量和数据量、预热/持续时间、目标 Agent 流量、商城现有 SLO、允许的延迟/错误率增量、数据库资源与连接池安全水位、06 中待补的下游额度。阈值未确定时只能记录测量结果，不能判定通过。

通过条件：DB02–DB05 的确定性保护断言全部通过，DB01/DB06 在冻结的业务与容量阈值内；不以 Agent 自身响应正常替代商城正常。超过任一硬阈值则降低 Agent 查询额度或修复接口后重测，不能直接提高阈值掩盖回归。
